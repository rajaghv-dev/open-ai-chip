# Add a tiny AI engine

The repo has 18 designs with the 24-pin stream interface (the count behind `make adapter-test`'s 14 is 13 classifier engines + kv_attn_n8; the other four KV variants are not in the adapter test). 13 are classifier-style engines built with one recipe: vision_all_lit, vision_block, text_sentiment (model/tiny_ai/), audio_pitch, audio_onset, image_text_match (own model dirs) and prec_{bin,tern,int4,int8,fp8,fp16,bf16} (model/precision_hw/, see the precision-variant skill). The other 5 are the KV-cache attention family kv_attn_{n4,n8,n16,n8_int4,n8_ring}, the example of a NON-classifier stream engine (below). Everything flows one way: spec -> train -> weights.json -> golden -> generated ROM + vectors -> RTL + testbench -> flow. The model is the source of truth; the RTL must match golden.py bit for bit. Details and file-by-file evidence: reference.md. Skeletons: templates/.

**KV family as a worked example of a different engine shape.** `kv_attn_*` is one attention head with a KV cache in registers: a command-frame protocol (RESET_CACHE / PREFILL / DECODE, 2- or 8-beat responses, 5 status codes), not "N inputs then 2 result beats". It has no trainer (parameters are hand-picked): `model/kv_attention/{spec.md,golden.py,gen.py}` (`gen.py` writes `designs/kv_attn_<v>/rtl/kv_attn_<v>_rom.v` and `tb/vectors.hex`, 1521 records for kv_attn_n8, 40-word records), one shared engine `shared/rtl/kv_attn_core.v` (parameters N, KVB, RING) wrapped by a thin `rtl/kv_attn_<v>.v`, and its own testbench body `shared/tb/kv_attn_tb.vh` run with `+VEC=`. `config.json` lists the ROM, then `dir::../../shared/rtl/kv_attn_core.v`, then the top. Wiring differs from the recipe below: `model-check` covers it (69 checks), `make check-generated` regenerates it, `tests/run_tests.sh` has a `KV` list and a vector-mutation negative test for kv_attn_n8, and `tests/adapter/run.sh` uses format `KV` (`kv_attn_n8:KV`). Background: `docs/LLM_INFERENCE.md`; the SoC side is `designs/soc_kv_attn_n8` and `make soc-kv` (soc-run skill). Copy `kv_attn_n8` when the new engine is command/response style or shares a core across variants.

Start by picking the closest existing engine and copy its files: frame engines (fixed-length input, two result beats) copy vision_block / text_sentiment / image_text_match; continuous-stream engines copy audio_pitch / audio_onset. `<eng>` below is the new name (lowercase, underscores).

## Step checklist

1. **Spec** `model/<eng>/spec.json`: stream contract (inputs, input_max, output beats, error rule, latency in clock edges counted from the edge accepting the last beat to the edge that raises m_valid, both counted), the label rule in words, model structure, parameter widths. Template: templates/spec.json.
2. **Fit** `model/<eng>/train.py`: exhaustive search over the whole parameter space against the full labelled truth table (the table lists every input, so zero mismatches means correct everywhere). Deterministic order, no randomness, fail non-zero if no exact fit. Writes `weights.json`. If the space is too big to enumerate, the dataset must be fixed-seed and golden.py --check must still be exact on it.
3. **Golden** `model/<eng>/golden.py`: `run(design, beats) -> (beat0, beat1, latency)` using only weights.json; `--check` evaluates the whole dataset and prints `<n> cases, 0 mismatches` per design, exit 1 otherwise; `golden.py <args>` prints one result. Standard library only. Template: templates/golden.py.
4. **Generator** `model/<eng>/gen_rom.py` writes `designs/<eng>/rtl/<eng>_rom.v` and `designs/<eng>/tb/vectors.hex`. Rules that earlier bugs forced:
   - header `// Generated by ... do not edit.` plus `// source sha256 <hash>` over weights.json, golden.py, gen_rom.py (and common.py, spec.json when they exist);
   - ROM uses **continuous `assign` only**. An `always @(*)` ROM whose inputs never change was never evaluated in simulation;
   - **write-if-changed** (compare, then write) so timestamps stay put; the flow's stale-run check compares timestamps;
   - vectors.hex in the 16-byte record layout (header `A5, count_hi, count_lo`; per case `[0]` beats, `[1..12]` s_data, `[13]` beat 0, `[14]` beat 1, `[15]` latency); cases = every valid input, short frames of every length, long frames, an out-of-range item at every position (values max+1 and 0xFF). Template: templates/gen_rom.py.
   - **Case limit**: shared/tb/stream_tb.vh has MAXREC = 1024, so at most **1023 cases**; assert it in gen_rom. Above that (image_text_match has 2,079) copy the body as `designs/<eng>/tb/stream_tb_big.vh` with a larger MAXREC and include it by repo-relative path.
   - Audio-style engines use their own 32-bit-word vector layout and a streaming testbench (no frames); read model/audio_pitch/gen_rom.py and designs/audio_pitch/tb/audio_pitch_tb.v.
5. **RTL** `designs/<eng>/rtl/<eng>.v`: header comment with THE NETWORK, NEURAL NETWORK <-> HARDWARE mapping and BLOCKS; code in labelled IO / MEMORY / COMPUTE / CONTROL sections; instantiate `<eng>_rom`. Template: templates/engine_header.v. Keep the stream protocol below exactly.
6. **Testbench** `designs/<eng>/tb/<eng>_tb.v`: five lines, `define DUT <eng>` then include `stream_tb.vh` (Makefile passes `-I shared/tb`). Template: templates/tb.v.
7. **config.json** `designs/<eng>/config.json`: copy a neighbour; conventions below. Template: templates/config.json.
8. **README.md** (property, task and model, hardware, 24-pin port list, Run, Files table) and **NOTES.md** (written after the flow, from output/ evidence; use the write-design-notes skill, and tests/run_tests.sh checks the required headings once output/metrics.json exists).
9. **Wire it in** (every list below; grep for a sibling name such as `image_text_match` to find them all):
   - `Makefile`: add `<eng>` to `ALL_DESIGNS` (macros before wrappers), and to `MODELS` if it has its own model dir; add train+gen_rom lines to `generate` and golden --check to `model-check`; the `help` text names "14 stream engines (incl. kv_attn_n8)" for `adapter-test` (update it when you add to the adapter list).
   - `tests/run_tests.sh`: add to `NEWENG` (structure, lint, sim loops follow from it); add a `golden.py --check` case in the `== model` loop; add a corrupted-vector entry in the "new engines" negative loop (record layout: word 13 of record 1 is expected beat 0); optionally an RTL-mutation case.
   - `scripts/check_generated.sh`: add the model dir to `FIT` (or its own generator line) and the design to the `for d in ...` list so ROM + vectors regeneration is compared.
   - `scripts/docs/tables.py`: add `<eng>` to `ORDER` (hardening order); README tables are regenerated with `make table` and `tests` runs `tables.py --check`.
   - `tests/adapter/run.sh`: add `<eng>:FRAME` (frame record layout; `PITCH`/`ONSET` only for the two audio layouts, `KV` for the kv_attn record layout) to `ENGINES` so the engine is reachable from the SoC through wb_stream_adapter; `adapter_tb.v` needs no change for frame engines.
   - README.md: engine list, results table markers refresh, the engine counts (README, `make help`).
10. **Verify, in this order** (each is a gate; fix and rerun, never weaken a check):
    1. `cd model/<eng> && python3 train.py && python3 gen_rom.py && python3 golden.py --check` -> every line `0 mismatches`.
    2. `make simulate DESIGN=<eng>` -> a `PASS <eng>_tb: <n> cases` line.
    3. **Negative test**: corrupt one expected value in a copy of vectors.hex and break one RTL line in a temp copy; the testbench must exit non-zero with no PASS line (this is what run_tests.sh's negative section does; assert each mutation really applied).
    4. `bash tests/adapter/run.sh` (or `ONLY="<eng>"`) -> `PASS <eng>` (the run ends `adapter tests: 14 engines PASS` today).
    5. `make flow-all DESIGN=<eng>` -> all 5 stages PASS (simulate, gds, check, gl_synth, gl_final; then collect). Several minutes in Docker.
    6. `make table` then `make test` -> `test: ALL PASSED`.
    7. `make check-generated` -> `PASS` (regeneration reproduces every generated file).
11. Commit nothing unless asked. Leave generated files exactly as the generators wrote them.

## Stream protocol (24 pins, all engines)

Pins: `clk`, `rst` (synchronous, active high), `s_valid`, `s_data[7:0]`, `s_last`, `s_ready` (out), `m_valid` (out), `m_data[7:0]` (out), `m_last` (out), `m_ready` = 24. Rules the shared testbench enforces on RTL and on both gate-level netlists:
- A beat moves when valid and ready are both high at the rising edge. Output beat 0 = `{6'b0, error, class}`; beat 1 = score byte with `m_last`.
- While `m_valid` is high and `m_ready` low, `m_valid`, `m_data`, `m_last` must hold.
- `s_ready` is low from the beat that carried `s_last` until the result was taken (no overlap of frames).
- Reset mid-frame and with a result waiting returns to empty and ready.
- `error` is set by an out-of-range item or a frame of the wrong length; beats past the expected count are accepted and ignored; the result is still produced. Comparisons use `!==` so X never passes.

## config.json conventions

- Copy a neighbour; keep `CLOCK_PERIOD 25`, `FP_SIZING absolute`, `RT_MAX_LAYER met4`, `RUN_ANTENNA_REPAIR`, `ERROR_ON_SYNTH_CHECKS true`, `MAX_FANOUT_CONSTRAINT 8`, VERILOG_FILES `dir::rtl/<eng>_rom.v` then `dir::rtl/<eng>.v`.
- **Slew margin 20**: set `PL_RESIZER_MAX_SLEW_MARGIN` and `GRT_DESIGN_REPAIR_MAX_SLEW_PCT` to 20. The 40 copied from vision_block made the post-placement repair run out of the 8 GB container twice (designs/image_text_match/config.json `//SLEW`).
- **Die ~40 % utilisation**: estimate std-cell area from the closest sibling's `output/metrics.json` (`design__instance__area__stdcell`), pick a square die (`DIE_AREA [0,0,N,N]`) giving about 40 %; 80 um copied from vision_block gave 82 % and an out-of-memory repair for image_text_match, 120 um gave about 36 %. Record the reasoning in a `//DIE_AREA` key. Compare cell area, not die area.

## Pitfalls

- Edit only inputs, never generated files; rerun the generator.
- Zero-extend unsigned inputs before signed arithmetic in RTL.
- State encoding: synthesis may recode the FSM one-hot, so surviving flops can exceed RTL bits; dead flops must be removed from the RTL or listed in scripts/flow/signoff_allowances.json with a verifiable reason (see precision-variant).
- Keep `README.md` claims tied to files; no absolute home paths in sources (run_tests structure check).
