LOCAL CHANGES
 1. rtl/user_project_wrapper.v: license header, module header, parameter, power ports, every port and the
    MPRJ_IO_PADS use are byte-identical to upstream (checked by diffing the module header through the port list). The
    user_proj_example instance is replaced by exactly one tiny_ai_core instance named mprj (SPEC.md), every port
    connected to the same-named wrapper port, irq -> user_irq, power pins vccd1/vssd1 under USE_POWER_PINS.
    The io_* buses are connected whole (the template sliced {io[37:30], io[7:0]} for its 16-bit example); no glue logic.
    analog_io and user_clock2 stay unconnected (SPEC). A "LOCAL CHANGE" note was added to the header comment.
 2. config.json, LibreLane 2 -> 3 key translation (names from the LibreLane 3.0.2 package, deprecated_names lists):
      FP_PDN_ENABLE_RAILS                 -> PDN_ENABLE_RAILS
      FP_PDN_{V,H}OFFSET/WIDTH/SPACING/PITCH -> PDN_{V,H}OFFSET/WIDTH/SPACING/PITCH
      FP_PDN_CORE_RING                    -> PDN_CORE_RING
      FP_PDN_CORE_RING_{V,H}{WIDTH,OFFSET,SPACING} -> PDN_CORE_RING_{V,H}{WIDTH,OFFSET,SPACING}
    Values are unchanged. All other template keys exist under the same name in LibreLane 3 and are kept as is
    (SYNTH_ELABORATE_ONLY, RUN_*, DESIGN_REPAIR_BUFFER_INPUT_PORTS, ERROR_ON_*, FP_SIZING, DIE_AREA, FP_DEF_TEMPLATE,
    VDD/GND_NETS, CLOCK_*, MAGIC_*, SIGNOFF_SDC_FILE, PNR_SDC_FILE, DRT_THREADS, MACROS, PDN_MACRO_CONNECTIONS, meta).
    Duplicate "//" comment keys became "//1".."//6" (LibreLane skips keys starting with "//").
    Added: PDK sky130A and STD_CELL_LIBRARY sky130_fd_sc_hd set explicitly. VERILOG_FILES now dir::rtl/.
    Not set (as in the template): RT_MAX_LAYER, DISABLE_LVS, MAX_FANOUT_CONSTRAINT (LibreLane default is used by signoff.sdc).
    MAX_TRANSITION_CONSTRAINT 1.5 and ERROR_ON_SYNTH_CHECKS false are the template's wrapper-level settings, not our change.
 3. MACROS: user_proj_example replaced by tiny_ai_core. Views come from build/macros/tiny_ai_core/ (created by
    'make views DESIGN=tiny_ai_core'; absent until then). The template maps lib "*" to one file; here lib is mapped per
    corner (*_tt_*, *_ss_*, *_ff_* -> nom_tt_025C_1v80, nom_ss_100C_1v60, nom_ff_n40C_1v95) so STA at every corner uses
    the matching library; spef keys min_*/nom_*/max_* as upstream. If the export lacks the ss/ff libs, use the single
    "*" entry for nom_tt_025C_1v80 instead.
 4. PDN_MACRO_CONNECTIONS "mprj vccd1 vssd1 vccd1 vssd1": the template example uses vccd2/vssd2 for its macro; tiny_ai_core
    is on vccd1/vssd1 per SPEC (user area 1 supply), so both the wrapper net and the macro pin are vccd1/vssd1.
 5. lvs_config.json: LVS_VERILOG_FILES names build/macros/tiny_ai_core/nl/tiny_ai_core.nl.v instead of
    verilog/gl/user_proj_example.v. For the later ChipFoundry precheck only; LibreLane does not read it. Other keys unchanged.
    The precheck's layout is $UPRJ_ROOT/gds/user_project_wrapper.gds and the layout needs the standard Caravel tree.
