# Agent context: what the agent needs to know first

Audience: the local Hermes agent (Open WebUI in the browser or the Mac app) and anyone writing its prompts.
Sources: `CLAUDE.md`, `README.md`, `SPEC.md`, `docs/SKILLS.md`, `scripts/flow/*`. Nothing here is measured data.

## What the repo is
`open-ai-chip`: small digital designs (tiny AI engines, a number-format precision study, KV-cache attention engines, a
Wishbone counter, SoC macros, Caravel wrappers), each taken from RTL to GDSII on sky130A (sky130_fd_sc_hd) with
LibreLane in Docker, as a learning build toward a ChipFoundry ChipIgnite (Caravel) tapeout. Clock 25 ns (40 MHz).
Design list and counts: README.md "The designs" table (the master prompt lists them, generated from it).

FLOW (make flow-all DESIGN=<d>, stages in order): simulate (iverilog self-checking tb), gds (LibreLane), check (signoff: DRC, LVS, timing, no lost logic), gl (gate-level sim, synthesised netlist), gl-final (routed netlist), collect (results into designs/<d>/output/).
CLEAN means: zero DRC and LVS errors, setup and hold met, no deleted logic, both gate-level sims PASS. Slew counts are reported, not a gate.

Never cf login/push/confirm, never tapeout or publish anything. One physical flow at a time. Generated files (ROM .v, vectors.hex, weights.json) come only from model/<x>/ via make generate. ## Design families (one line each)
- Baseline `user_proj_example`: the Caravel template counter; its RTL must stay byte-identical (tests/upstream.sha256).
- Tiny AI engines (`vision_all_lit`, `vision_block`, `text_sentiment`, `audio_pitch`, `audio_onset`, `image_text_match`):
  small neural blocks with weights folded into logic, a 24-pin valid/ready stream interface, models in `model/<x>/`.
- Precision study (`prec_bin`, `prec_tern`, `prec_int4`, `prec_int8`, `prec_fp8`, `prec_fp16`, `prec_bf16`): one 9-input
  neuron in seven number formats; only the arithmetic differs (docs/PRECISION_STUDY.md).
- KV-cache attention (`kv_attn_n4`, `kv_attn_n8`, `kv_attn_n16`, `kv_attn_n8_int4`, `kv_attn_n8_ring`): one attention
  head with a KV cache in registers behind a command-frame protocol (docs/LLM_INFERENCE.md, model/kv_attention/spec.md).
- SoC macros (`tiny_ai_core`, `soc_image_text_match`, `soc_kv_attn_n8`): Wishbone engine core and PicoRV32 SoCs
  (docs/SOC_PLAN.md, firmware/, soc_sim/).
- Caravel wrappers (`user_project_wrapper`, `_soc_itm`, `_soc_kv`): the macros inside Caravel's fixed wrapper
  (fixed geometry never changes).

## The flow and what "clean" means
`make flow-all DESIGN=<d>` runs simulate, gds, check, gl, gl-final, collect and stops at the first failing stage; it is
capped at 10 minutes (FLOW_TIMEOUT 600 s). A finished run is reused unless a non-markdown file in the design dir
changed (scripts/flow/find_reusable_run.py). `make test` is the fast gate (about 100 to 125 s, no Docker). `make doctor`
checks Docker, the LibreLane image and the PDK before any physical flow. Failure patterns (out of memory, GPL-0301,
GRT-0116 congestion, hold or slew violations, "logic lost") are in `.claude/skills/harden-design/SKILL.md`.

## Where evidence lives
- Per design: `designs/<d>/NOTES.md` (the design page), `designs/<d>/output/metrics.json`, `resources.json`
  (wall time, peak memory), `flow.log`, `layout.png`, `reports/` (synthesis, timing, DRC, LVS).
- Tables: README.md results block (generated by make table), `docs/RESULTS.md`, `docs/VALIDATION.md`, `docs/LESSONS.md`.
- Stage logs: `build/flow/`; results copies: `build/results/<d>/`; agent jobs: `build/agent/jobs/`; memory:
  `build/agent/memory/`.

## Hard rules in plain words
Source: CLAUDE.md "HARD RULES".
- Never run `cf login`, `cf init`, `cf push`, submit, reserve or `cf confirm`; never publish anything; never make the
  GitHub repository public. Those are the owner's own actions.
- Never loosen `MAX_TRANSITION_CONSTRAINT` or the 25 ns `CLOCK_PERIOD` to make a gate pass; never disable LVS; never
  weaken DRC, LVS, timing or precheck; never accept deleted logic without a reason verifiable in the RTL.
- Never change the fixed wrapper geometry or pin locations. Never edit the sibling `../open-ai-silicon`.
- One physical flow at a time (check running jobs first).
- Never hand-edit generated files; change the model and run `make generate`.
- Every number in an answer comes from a file or tool result; say which. Unknown means say unknown.
- This agent reads and runs make targets; it does not edit files. Edits go to Claude (`claude_task` or Claude Code).
  `run_make` and `claude_task` need the user's confirmation: the first call returns a confirm_id and the user replies
  "yes, run <id>".

## Skills
Six project skills in `.claude/skills/` (guide: docs/SKILLS.md). The `skill_plan` tool returns the ordered steps and the
tool for each step:
- harden-design: RTL to clean GDSII, diagnose failures. Agent: run flow-all, then run_summary, diagnose, suggest.
- soc-run: soc-sim, soc-kv, adapter-test, caravel-rtl, caravel-gl.
- wrapper-build: views export and the wrapper flow.
- write-design-notes, precision-variant, add-tiny-engine: edit files; the agent gives the plan and hands over to Claude.

## How to ask the agent
Short, concrete, with the exact design name: "How many cells does kv_attn_n8 have?", "Compare kv_attn_n8 and
kv_attn_n8_int4", "Show kv_attn_n8 met1 lower-left 50 um", "Plan hardening for kv_attn_n8" (skill_plan), "Run make
simulate for vision_block" (then answer yes to the confirm), "Remember: I prefer areas in um2". A question starting
with How, What, Which or Why is answered in words; only "Run make <target> for <design>" starts a job.
Slash prompts in Open WebUI: /harden, /soc-run, /wrapper, /notes, /precision, /add-engine.

## Memory
Local markdown in `build/agent/memory/` (never committed): `MEMORY.md` index, topic files (remember, recall, forget),
`runs.md` (automatic run history: date, design, command, result, key numbers, log path). The `context_brief` tool and the
optional Open WebUI filter (`examples/hermes_desktop/memory_filter.py`) bring the digest into the conversation.
