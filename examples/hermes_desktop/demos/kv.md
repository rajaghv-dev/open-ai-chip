## Act 3: The same story at LLM scale: prefill is compute-bound, decode is memory-bound.

Look for: docs/LLM_INFERENCE.md section 1.

According to the search_docs tool, the difference between prefill and decode in the context of LLM inference on a chip is as follows:

- **Prefill is compute-bound**: One prefill frame pays the fixed costs (bus setup, opcode beat, wait, and response), and each additional prompt token adds only one 51-cycle bus write and one engine cycle. The cost per prompt token decreases with the number of tokens (P), making prefill compute-bound.

- **Decode is memory/latency-bound**: Every generated token requires its own frame, involving two writes, a wait, and eight response reads, taking 670 cycles. This is significantly higher than the cost of prefill, making decode memory/latency-bound.
