## Act 1: Seven copies of the same 9-input neuron, one per number format, each taken to clean GDSII.

Look for: accuracy column: 94.0 to 94.25 percent for tern, int4, int8, fp8, fp16, bf16; cells grow from 199 to 1932.

The lesson is that while all these precision formats achieve similar accuracy (between 94.00% and 94.25%), the silicon area grows significantly from 1473.91 um2 for the 4-bit count accumulator up to 11912.7 um2 for the fp16 format. Ternary and int4 have the smallest area, even though they have more bits than the 4-bit count. This is why ternary and int4 are preferred for this neuron design.

## Act 2: Why do ternary and int4 win? Same accuracy, a fraction of the area. Here is the written reason.

Look for: the quoted NOTES.md paragraph and its file and line numbers.

According to the design notes for prec_tern, the main reason ternary wins is accuracy. It achieves 94.15% test accuracy, which is equal to the full precision 32-bit (fp32) format within noise (94.05%). The ternary format recovers all the lost accuracy at 27 parameter bits, which is twice the storage per weight compared to the binary format.

The key advantage of ternary over binary is that it can represent zero as a weight, which the binary format lacks. This allows ternary to match the accuracy of the more complex fp32 format while using less storage and power.

In summary, ternary achieves fp32-level accuracy with 1.47x the standard cells and 1.36x the power of binary (293 vs 199; 1.439e-4 vs 1.055e-4 W), making it the cheapest format with no accuracy penalty on this task.
